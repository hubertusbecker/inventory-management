End-to-End Data Flow

Filter Pipeline

1
User selects a filter in FilterBar.vue (Period, Location, Category, Status)
2
useFilters() reactive ref updates — all views share the same singleton state
3
Component watch() detects change, calls loadData()
4
api.js builds URLSearchParams — omits params set to 'all'
5
FastAPI apply_filters() + filter_by_month() reduce in-memory data
6
Filtered JSON returned → Vue computed properties derive charts & metrics

Key Architecture Patterns

Shared Filter State

A single useFilters() composable provides reactive filter state to all views. Every page watches the same refs — changing a filter in the header updates all open views simultaneously, with no prop drilling or event bus.

Computed Property Calculations

Raw data arrives from the API as refs (allOrders, inventoryItems). Derived values — KPIs, chart data, top products, on-time rates — are all computed() properties. No data is mutated; views re-derive automatically.

Client-Side SKU Matching

Demand and Backlog data have no warehouse/category fields. The frontend applies location and category filters by cross-referencing SKUs against the filtered inventory list — keeping the backend simple while preserving full filter semantics.

Modal Detail Views

Detailed information is shown in overlay modals (ProductDetailModal, InventoryDetailModal, BacklogDetailModal, CostDetailModal) rather than separate routes. Users stay in their filtered context while drilling into individual records.

In-Memory Data Layer

mock_data.py loads all JSON files at server startup into module-level variables. No database — all queries are Python list comprehensions with filter functions. Fast for demos; swap for a real DB by replacing the data accessors.

i18n & Currency

useI18n() stores locale in localStorage. Switching from English to Japanese automatically changes the currency symbol (USD → JPY) and translates product names, customer names, and warehouse labels throughout the UI.
